# CANN Bench 实测：kernel-agent 当前能写出的算子质量

日期：2026-11-08
设备：m18 `kylin10-6018` / Ascend910B4-1（`ASCEND_RT_VISIBLE_DEVICES=1`）
环境：容器 `deepinfer-real`，CANN 9.1.0，torch 2.10.0+cpu，torch_npu 2.10.0.post4
模型：`deepseek-chat`（DeepSeek OpenAI 兼容端点）
测量：CANN Bench 官方正确性用例 + 官方 bench；`bench_rounds=3`，速度比为 3 轮中位数。

## 最终解独立复评（不是只取训练过程中最好的那次）

| 任务 | 官方正确性 | vendor 速度比（95% CI） | agent 最终解速度比（95% CI） | agent / vendor | 最差用例（vendor → agent） |
| --- | --- | --- | --- | --- | --- |
| add（elementwise） | **12/12 通过** | 0.7926 [0.7484, 0.8067] | **1.0113** [0.8811, 1.0430] | **1.2759x（快 27.6%）** | 0.755 → 约 0.88（最差用例区间见原始结果） |
| swi_glu | **12/12 通过** | 2.4293 [2.2907, 2.4551] | **2.3554** [2.2755, 2.3812] | **0.9696x（慢约 3.0%）** | 2.0926 → 2.0772 |
| rms_norm | **6/6 通过** | 4.0468 [4.0378, 4.2238] | **4.0158** [3.9842, 4.0348] | **0.9923x（慢约 0.8%）** | 2.5659 → 2.6066 |

绝对耗时（bench 汇总，单位 ms）：

- add：vendor candidate 0.193975 → agent candidate **0.161764**；baseline 从 0.145167 → 0.168722。
- swi_glu：vendor candidate 0.614145 → agent candidate **0.678780**；baseline 从 1.543471 → 1.653379。
- rms_norm：vendor candidate 0.473381 → agent candidate **0.482309**；baseline 从 1.871060 → 1.900978。

## 结论

**当前 kernel-agent 已经能写出“正确且可运行”的 AscendC 算子，但还没有稳定超过已优化的 vendor 脚手架。**

- 简单 elementwise（add）上，agent 写出了通用 tiling + 多缓冲队列 + 尾部处理，**比 vendor 快约 28%**，而且最终解与 vendor 的 CI 不重叠，说明这次提升是真实的。
- 中等复杂度（swi_glu、rms_norm）上，结果与 vendor 基本同档（±3% 和 ±1%），CI 大幅重叠，**没有显著超越**。
- 最好的单次迭代不等于最终质量：例如 RMSNorm 训练过程最好一次为 4.1516x，但最终解独立复评为 4.0158x。评估应以最终解的独立复评为准。

## 证据细节

- add：2 次实际评测，速度从 0.8312 提升到 1.0245；最终解独立复评 1.0113。说明 agent 能在第二次迭代中修正 tiling/对齐，得到实际收益。
- swi_glu：1 次实际评测，2.3332；最终解独立复评 2.3554。过程中出现过 `find text occurs 2 times` 的 patch 拒绝，模型随后读取文件并修正 patch，说明修复后的 read_file/patch 反馈确实送到了模型。
- rms_norm：第一次 run 只是 `run_eval`（没有修改文件，不能算作 agent 产出，已排除）。第二次 run 中模型对 `row_ops_plugin.cpp` / `row_ops_kernel.cpp` 做了 3 组小编辑，3 次评测为 4.1516 / 3.9034 / 4.0352，最终解独立复评为 4.0158。

## 未覆盖 / 限制

- `swi_glu_950` 没有 `bench_command`，且 m18 是 910B，不是 950，因此没有纳入加速比结论。
- 本轮没有留出新形状（holdout）评估；官方用例通过只能证明这些用例上的正确性，不等于所有形状/输入分布都正确。
- 只测了 deepseek-chat 这一款模型；不能推广到其它模型。
- 测试期间 m18 是共享机器，速度比用同一任务、同一设备的 vendor/agent 对照降低干扰，但小样本下仍应视为单次实测，不是稳定性能承诺。
